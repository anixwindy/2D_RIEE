# codebook 條目格式 —— 複製這個當範本

> 新增一支模板時,把下面整塊貼到檔案最上面,再把欄位填掉。
> **標頭是給三個月後的你看的,不是給現在的你看的。**

---

## §0 標頭範本(複製這塊)

```cpp
// ══ <這支叫什麼> ═══════════════════════════════════════
//  用途   : 一句話。什麼時候該想到它
//  複雜度 : O(...)  <- 前處理和查詢分開寫
//  等級   : 灰 / 綠 / 青 / 藍 / 紫 / 橙 / 紅
//  驗證   : [  ] 還沒用它 AC 過
//  坑     : 1. ★ 最容易錯的那一個
//           2. 第二容易錯的
//           3. 什麼情況「不能」用它
// ═══════════════════════════════════════════════════════
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

// ── 主體 ────────────────────────────────────────
// (函式 / struct。這一段是你會複製走的部分)

int main() {
    // 示範用法 + 把預期答案寫在行末註解
    // cout << f(5) << "\n";   // 7
    return 0;
}
```

---

## §1 六個欄位,每個都有理由

| 欄位 | 為什麼一定要有 |
|---|---|
| **用途** | 三個月後你不會記得這支在幹嘛。**寫「什麼時候該想到它」,不要寫「它做什麼」** |
| **複雜度** | 決定「這題 n 這麼大能不能用」。**沒寫等於要重推一次** |
| **等級** | 讓你知道「這支我現在該不該碰」。超前兩級的先不要看 |
| **驗證** | ★ **最重要**。沒 AC 過的模板不能信,見 `README.md` §2 |
| **坑** | ★★ **這欄的價值超過程式碼本身**。程式碼網路上到處都是,**但「你上次在哪裡錯」只有你自己知道** |
| **示範 main** | 讓你能直接跑起來確認,不用另外找測資 |

---

## §2 ★ 「坑」這一欄怎麼寫

**不要寫理論,寫你實際踩過的。**

| 差的寫法 | 好的寫法 |
|---|---|
| 「注意邊界」 | 「01 背包容量迴圈要**由大到小**,寫反會變成完全背包,而且不會噴錯」 |
| 「小心溢位」 | 「INF 設 4e18,兩個相加就爆 -> 用 `LLONG_MAX / 4`」 |
| 「要初始化」 | 「多筆測資忘記重新 init DSU,第二筆會用到第一筆的殘留」 |

**判準:三個月後的你讀了這一行,能不能直接避開那個錯?**

**⚠ 每次因為某個坑 WA 掉,回來把它加進這一欄。這是 codebook 真正在長大的地方。**

## §3 命名規則

| 規則 | 例 |
|---|---|
| 資料夾 = 兩位數字 + 底線 + 領域 | `04_dp` |
| 檔名 = 全小寫 + 底線,不要縮寫到看不懂 | `segtree_lazy.cpp` 不要寫 `sgt.cpp` |
| 一個檔案可以放同一主題的多個變體 | `knapsack.cpp` 裡放 01 / 完全 / 多重 |
| 一個檔案不要超過 150 行 | 超過就拆 |
