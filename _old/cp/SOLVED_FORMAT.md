# 解題記錄格式 —— 這才是真正的積累物

> **codebook 存「怎麼寫」。這裡存「怎麼想到的」。**
> 分數上不去的時候,值錢的是後者。

---

## §0 為什麼要記(先講,不然你不會記)

你說 CP「不能積累」。真相是:

| 東西 | 會不會自己留下 |
|---|---|
| rating | ✅ 平台自動記 |
| 程式碼 | ✅ 平台自動存 |
| **「我卡在哪一步」** | ❌ **完全蒸發,而且這是唯一會讓你變強的東西** |
| **「這題為什麼想得到用那個演算法」** | ❌ 同上 |

**→ 這個資料夾就是把第 3、4 列留下來。**

---

## §1 檔名規則

```
cp/solved/YYYY-MM-DD_平台題號_簡短標題.md
```

例:`cp/solved/2026-09-07_CF1234D_knapsack-with-limit.md`

同一天可以有多個。**檔名裡放日期,排序就是時間軸。**

---

## §2 範本(複製這塊)

```markdown
# <題號> <標題>  (rating: <分數>)

| | |
|---|---|
| 連結 | <網址> |
| tag | <dp / graph / greedy ...> |
| 花了多久 | <分鐘> |
| 結果 | AC 一發 / WA N 次後 AC / 看題解才會 / 沒解出來 |

## 題目一句話
<用你自己的話,不要抄題目>

## 卡在哪
<★ 最重要的一欄。想不到什麼?哪一步斷掉?>

## 關鍵想法
<那個「喔原來如此」的點是什麼>

## 怎麼想到的 / 如果沒想到,線索在哪
<★ 第二重要。下次看到什麼特徵應該聯想到這招>

## 用到的 codebook
<codebook/04_dp/knapsack.cpp — 有沒有需要改?>

## 犯的錯
<WA 的原因。★ 這一條要同步加進 codebook 該支的「坑」欄>
```

---

## §3 四個欄位的填法(其他都可以隨便)

| 欄位 | 怎麼填才有用 |
|---|---|
| **卡在哪** | 寫「**我試了 X,失敗因為 Y**」,不要寫「太難了」 |
| **怎麼想到的** | ★ 寫「**題目裡的哪個字/哪個數字範圍**讓我聯想到這招」。這是唯一能遷移到下一題的東西 |
| **犯的錯** | 寫具體的:「`int` 沒開 `long long`」「二分邊界寫成 `mid-1` 無限迴圈」 |
| **結果** | ★ 「**看題解才會**」要誠實寫。三個月後回看,這一欄的比例就是你的真實進步曲線 |

---

## §4 ⚠ 一個防止這件事變成負擔的規則

**一題最多寫 5 分鐘。寫不完就交白卷,不要因為「要寫記錄」而不敢解題。**

| 情況 | 記錄要求 |
|---|---|
| AC 一發、覺得很簡單 | **只寫檔名 + 一行 tag 就好**,甚至可以不寫 |
| WA 過 / 想很久 / 看了題解 | **完整寫**。這種才是有價值的 |
| 完全不會 | **一定要寫**。這是最值錢的一種 |

**判準:如果你開始覺得「因為要寫記錄所以不想解題」,那就是規則訂太緊了,立刻放寬。**
